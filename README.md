# 机车检查作业系统 · HXD3D

按 HXD3D 型电力机车检查部位组织的交互式教学系统，复用「电力机车数字孪生系统 V2.3」的三维模型与界面语言，提供从车顶到车钩 8 个部位、44 个检查项的引导检查、勾选确认、异常登记与结果汇总。走行部升级为「零部件级检查」：以实测几何建立独立碰撞代理与交互代理，学生须走到对应位置、面向并观察具体部件后方可完成检查。

## 三、启动方式

### Windows 一键启动

双击根目录下的 `启动机车检查作业系统.bat`，脚本会：

1. 切换到本应用所在目录；
2. 调用 Node.js 启动本地静态服务器（默认 8777 端口）；
3. 自动在默认浏览器打开 `http://localhost:8777/机车检查作业/index.html`。

启动后控制台会显示服务地址、模型来源与"按 Ctrl+C 退出"。

### 手动启动

```bash
cd 资源/机车检查作业
node tools/serve.js            # 默认 8777 端口
# 浏览器访问 http://localhost:8777/机车检查作业/index.html
```

更换端口：`node tools/serve.js 8788`

### 关闭服务

在弹出的命令行窗口中按 `Ctrl + C`，或直接关闭该窗口。

## 四、操作要点

1. **步骤导航**：左侧"检查流程"8 个部位，点击切换；底部"上一部位/定位部位/下一部位"快捷操作。
2. **视图切换**：顶部"整车 / 端部 / 左侧 / 右侧 / 顶部 / 底部"6 个视角按钮。
3. **三维联动**：点击三维模型对应位置，系统会自动定位到最近检查部位；车顶、车钩按真实节点高亮，其它部位按空间区域高亮（带呼吸光效的青色线框与地面投影）。
4. **检查项操作**：
   - 展开/收起：点击检查项标题；
   - **合格**：点击"✓ 检查合格"按钮，项变绿色；
   - **异常**：点击"! 登记异常"，填入"异常现象描述 / 处置方式 / 处置时限"，项变红色；
   - **清除**：清除本项记录。
5. **顶部全部展开**：右侧面板标题栏可一次性展开/收起所有检查项。
6. **结果汇总**：底部"结果汇总"按钮打开报告，可"导出 CSV"或"打印"。
7. **断点续检**：检查记录自动保存到浏览器本地（localStorage），下次访问自动恢复；点"清空重检"重新开始。

## 五、模型加载策略与取舍说明

### 资源现状

核查 `资源/机车数字孪生/` 后确认：

- **三维模型 4 个版本**（hxd3d-integration.glb / hxd3d-web.glb / hxd3d-integration-optimized.glb / hxd3d-integration-spatial.glb），均放在 `01-系统程序（V1至V2.3）/hxd3d-digital-twin/public/models/hxd3d/`。
- **6 张部位教学卡**（pantograph / front-end / rear-end / left-side / right-side / running-gear）。
- **three.js 0.180** 依赖完整存放在 `node_modules/.pnpm/three@0.180.0/node_modules/three/`（顶层 `node_modules/three` 是空存根，因为 pnpm 符号链接未随文件夹迁移）。

### 取舍与决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 模型获取方式 | **相对路径引用原平台**（`../机车数字孪生/.../hxd3d-integration-spatial.glb`），未复制到本地 | 不修改、不复制原平台文件；不占 34MB 重复空间。如仅拷贝本文件夹运行，请把模型放到 `models/hxd3d-integration-spatial.glb`，系统会自动优先加载。 |
| 模型版本 | `hxd3d-integration-spatial.glb`（35MB） | 原平台 V2.3 实际使用的版本；6 个独立节点（车体 + 受电弓×2 + 车钩×2）已是最适合本任务的版本。 |
| three.js 获取 | 从 `.pnpm/three@0.180.0/node_modules/three/build` 与 `examples/jsm/` 复制到本项目 `lib/three/` | 完全离线，无需外网；体积约 2.1MB；依赖链已自洽（GLTFLoader → BufferGeometryUtils、OrbitControls）。 |
| 部位高亮方案 | **混合定位**：受电弓 / 车钩按真实节点高亮（emissive 蓝发光）；司机室 / 机械间 / 走行部 / 制动 / 端部 / 信号 按"归一化空间区域"高亮（半透明青色盒 + 边框线 + 地面投影 + 呼吸光效） | 见下条。 |

### 模型结构的关键发现与取舍理由

通过解析 GLB 内部结构确认：

```
hxd3d-integration-spatial.glb
├── HXD3D_WEB_OPTIMIZED_ROOT
│   ├── Static_Main_Body         ← 整车主体：合并后的单一 Mesh
│   ├── Pantograph_Controllable  ← 受电弓 1
│   ├── Pantograph_SourceLowered ← 受电弓 2
│   ├── Coupler_NegativeX        ← 车钩 1
│   └── Coupler_PositiveX        ← 车钩 2
```

- **走行部、制动系统、司机室、车体侧等部位没有独立网格**，全部合并在 `Static_Main_Body` 一个 Mesh 内，无法按 mesh 单独高亮；
- 优化版的模型更是只有 1 个根节点 / 1 个 Mesh。

因此本系统采用**混合定位方案**：
- 受电弓、车钩（有真实节点）→ 读取节点世界包围盒，按材质 emissive 蓝发光实现精确高亮；
- 其他部位 → 用归一化空间分区（u 沿车长 / v 沿车高 / w 沿车宽）按模型实时 `Box3` 换算，配合半透明盒 + 边框线 + 地面投影，给人"区域定位"的视觉感受。
- 点击拾取：raycaster 命中车体后取交点坐标，落入哪个分区就触发哪个部位。

### 如需更精细部位定位怎么办

需要把 HXD3D 模型按部位重新分块（玻璃器、转向架、车钩等拆成独立 mesh），生成新版 GLB。本项目暂未做这一步——

- 一方面避免动原孪生平台的优化模型；
- 另一方面教学层面"空间区域高亮 + 真实节点高亮"的混合方案已经能覆盖 8 个部位的直观定位。

如确实需要 mesh 级别部位模型，可在 `资源/机车数字孪生/02-三维模型处理与验证/` 下找到 Blender 源文件，按部位拆 mesh 后导出为新 GLB 放入 `机车检查作业/models/`，系统会自动优先加载本地副本。

## 六、缺失与建议补充

| 项 | 现状 | 建议 |
|----|------|------|
| 司机室 / 制动柜 / 机械间 等部位的内部 mesh | 缺失（已合并到车体） | 重新分块建模（投入 1~2 工日） |
| 制动机试验过程的动画演示 | 缺失 | 在 `scripts/` 中添加 Three.js 动画（管路压力变化、闸片动作） |
| 多机型支持 | 当前只支持 HXD3D | 复制 `inspectionData.js` 改车型，重做模型导入路径 |
| 检查结果 PDF 导出 | 当前仅 CSV / 打印 | 引入 `pdfmake` 或后端；纯前端可考虑 `print` API + 自定义样式 |
| 离线多用户 | localStorage 限制 | 引入轻量后端；或在检查完成后归档到 Excel/PDF |

## 七、故障排除

| 现象 | 原因 / 处理 |
|------|------------|
| 启动 bat 后浏览器打不开 | 检查控制台端口是否被占用；换端口 `node tools/serve.js 8788` |
| 页面卡在加载层不动 | 检查控制台报错；常见为 `node_modules` 没完整迁移（需保持原平台 `node_modules/.pnpm` 存在）；本系统已自带 `lib/three`，无此依赖 |
| 三维模型加载失败 | 1) 原平台文件夹被移动 / 重命名；2) 服务器 root 不是 `资源/`。解决方案：将模型放到本目录 `models/` 下作本地副本 |
| 看不到车钩、受电弓高亮 | 模型不是 spatial 版本。检查 `机车数字孪生/.../public/models/hxd3d/` 下文件 |
| 异常登记后没保存 | 检查浏览器是否禁用 localStorage（隐私模式 / 第三方 Cookie 限制） |
